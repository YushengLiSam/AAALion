## 1. 修复前(f9972f6,读码确认)

| 问题 | 表现 |
|---|---|
| 只用第一张图 | 多图消息里第 2、3 张不参与检索 |
| 文字被忽略 | "这个有没有便宜点的 / 500 以内的 / 不要日系" 和纯图返回一模一样的 CLIP top-3;文字只在 CLIP 一件都没返回时才用 |

## 2. 修复后的流程

```
图片(最多 IMAGE_MAX_QUERY_IMAGES 张)
  └─ CLIP ViT-B/32 各取 top-IMAGE_RECALL_N,按商品取最大相似度合并      query_images
       └─ 每个候选:相似度 < IMAGE_MIN_SIM → 丢弃;全部低于下限 → below_floor
            └─ 锚点 = 视觉最相似商品;候选钉在锚点的品类上                  pin_to_anchor_category
                 └─ 文字硬约束(本地规则,严格执行,不做 fail-soft)           apply_constraints
                      ├─ 有幸存 → 文字有描述 ? 交叉编码器融合排序 : 视觉顺序 → top IMAGE_TOP_K   (visual)
                      └─ 全被筛掉 → 锚点品类里按同一组约束走文字检索           (constraints_emptied)
```

### 2.1 硬约束(全部本地,不调 LLM)

* **结构化约束**:与文字路径同一套解析——本轮 `build_retrieval_filter` + 会话
  `build_conversation_filter`(带 `req.filters` 与历史),`apply_product_filter(strict_cny_price=True)`,
  外币商品先按汇率归一化成人民币再比价。品牌排除额外做别名展开("不要 Apple" 也排除 "Apple 苹果")。
* **本地否定**(`local_negation`,`negation.extract_negation` 的无 LLM 版本):否定语境里的品牌、
  国别词(日系/韩系/美系…)、"X以外/之外"、"国产/国货"(**严格**,文字路径里是筛空就放弃的 fail-soft)、
  否定语境里的属性词("不要黑色的" → 只按**标题**排除,比文字路径的"标题+描述"更保守,
  避免描述里写着"不含酒精"的商品被"不要含酒精"误杀)。
* **相对价格**:"便宜点 / 更便宜 / 太贵了" → 价格 < 锚点人民币价;"贵一点 / 更高端 / 太便宜" → 价格 > 锚点价。
  用户写了具体金额时以金额为准。"好一点 / 质量好点"是品质不是价格,**不**当成价格约束;
  紧跟在否定后面的价格词("不要便宜的 / 不是要更贵的")不算方向("不要太贵 / 不要太便宜"例外,意思不变)。
* **问句规整**:`是不是 / 要不要 / 有没有` 先折叠(否则 "是不是苹果的" 里的 "不是苹果" 会被当成排除);
  **辨认式提问**("这是不是苹果的 / 这是华为的吗 / 什么牌子")**所在分句**里点名的品牌不当成 `brand_include`
  ——否则图里明明是华为,问一句"是苹果的吗"就把华为筛掉了。其他分句里的品牌要求照常执行
  ("这是什么?我只要华为的" 仍只出华为)。
* **历史约束与照片冲突**:照片本身就是本轮话题。会话里继承的品类 / 细分品类与锚点对不上、
  且本轮文字没重新指定品类时,视为换话题:丢掉继承的品类、细分品类、预算和点名品牌,
  只保留跨轮排除(品牌 / 国别);继承的点名品牌与照片品牌不同也丢掉。

### 2.2 品类钉住

下限放得低(0.51),top-20 里常混进外观相近的别类商品。默认只保留与锚点**同大类或同细分品类**的候选,
相似度与锚点相差 < `IMAGE_CROSS_CAT_MARGIN`(0.03)的近似并列不限制。用户在要**替代品**
(相对价格 / 金额 / 任何排除 / 品牌要求)时收紧到锚点的**细分品类族**(`anchor_kind`:
细分品类 + `constraints._SUB_CATEGORY_RULES` 里 ≤4 项的同组,例如耳机族三个细分品类)。
用户文字自己指定了品类时由 Filter 决定,不钉。

### 2.3 文字融合排序

只在文字有**描述性内容**时启用:剥掉指代/询价/有无套话("这个 / 同款 / 这是什么 / 多少钱 / 有没有")、
价格短语、否定从句、产地词之后还剩 ≥2 个汉字或 ≥3 字母的英文词(如 "有没有黑色的"、"适合跑步的")。
交给交叉编码器的 query 是去掉否定从句和价格短语的原文(否定从句进交叉编码器会把被排除的品牌打高分)。

```
final = clip_sim + λ · ce_score        λ = IMAGE_TEXT_WEIGHT = 0.10
```

`clip_sim` 为 CLIP 余弦相似度(主信号),`ce_score` 为本地 bge 交叉编码器的 sigmoid 分(sentence-transformers 3.2
单输出 CrossEncoder 默认 sigmoid;融合前再截到 [0,1],换成输出 logit 的模型也不会让文字翻盘)。
文字最多贡献 0.10,只能在视觉相似度相差不到 0.10 的候选之间调整先后,视觉上明显更像的商品不会被翻盘。
交叉编码器出错 → 保持视觉顺序。

### 2.4 三种"没有视觉卡"的去向

| status | 条件 | 去向 |
|---|---|---|
| `below_floor` + 文字有内容(有描述,或带品类/品牌/预算) | 视觉最高分 < 下限 | 走普通文字检索(`top_k(llm_free=True)`,k=5),告诉 LLM "没找到与图片相似的,下面是按文字找的" |
| `below_floor` + 无文字 / 纯指代("这是什么") | 同上 | **不出卡**,告诉 LLM 如实说目录里没有相似商品 |
| `constraints_emptied` | 视觉相似的都不满足条件 | 在锚点细分品类族里按同一组约束走文字检索(`top_k(skip_topic_switch=True, llm_free=True)`),空了再放宽到大类;结果再严格过一遍本地否定;query / intent 里删掉所有否定触发词(排除条件已在 Filter 里;规整时删单字可能**拼出**否定词,如 "我不是考虑这个颜色" → "不考虑颜色",所以最后再整体清一遍)。告诉 LLM 视觉相似的不满足条件 |
| `no_visual` | CLIP / 图片索引不可用 | 走文字检索兜底(与旧行为相同,只是 `llm_free=True`) |

### 2.5 Prompt 附加段(第 11 条)

* `visual`:卡片按视觉相似度检索(及是否按文字排序);图中商品不一定在目录里,视觉判断与卡片一致时才确认同款;
  **列出已在卡片上强制执行的条件**,要求回复不要说某张卡超预算 / 属于被排除品牌;锚点被条件排除时点明。
* `constraints_emptied` / `below_floor`:见上表。SSE 事件类型、商品卡字段都没变;响应缓存 key 加了 `|img=<status>`,
  开关切换不会回放另一条路径的缓存。

### 2.6 语言

纯图消息不再用占位串判断语言:UI 选英文 → 英文;有文字 → 按文字;纯图 → 沿用上一条带文字的 user 轮语言,
都没有就中文。纯文字请求的判断不变。

## 3. 开关

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `IMAGE_TEXT_FUSION` | `1` | `0` → 旧行为(第一张图 CLIP top-3)。融合路径任何异常也自动回退旧行为(日志 `image+text fusion failed`) |
| `IMAGE_RECALL_N` | `200` | 每张图的 CLIP 召回数(1338701 起 ≥ 目录规模:全量排名再按硬约束掩码) |
| `IMAGE_RERANK_POOL` | `20` | 级联里交叉编码器只排视觉分最高的前 N 个幸存者 |
| `IMAGE_MAX_QUERY_IMAGES` | `3` | 参与视觉召回的图片数上限(LLM 仍看到全部图片) |
| `IMAGE_TOP_K` | `3` | 出卡数 |
| `IMAGE_MIN_SIM` | `0.51` | 视觉相关性下限(余弦相似度,Chroma / Milvus 同口径) |
| `IMAGE_TEXT_WEIGHT` | `0.10` | 融合公式里的 λ |
| `IMAGE_CROSS_CAT_MARGIN` | `0.03` | 品类钉住的近似并列余量;负数 = 关闭品类钉住 |
| `IMAGE_TWO_PATH` | `1` | 两路召回 + 商品级 RRF(见文末「做法 C」);`0` → 本节以上描述的级联。两路模式任何异常也回到级联 |
| `IMAGE_TEXT_PATH_K` | `10` | 文字路取多少个商品参与 RRF |
| `IMAGE_TEXT_PATH_PHOTO_ONLY` | `1`(**生产 `0`**,见文末 VM 实测) | 只发照片 / 没有描述性文字时也跑文字路(用视觉锚点的离线图片描述当 query) |
| `IMAGE_PIN_SIM` | `0.85` | 视觉最高分 ≥ 此值时锚点钉在第 1 位(用户在要"别的 / 其他款"时不钉) |
| `IMAGE_PIN_PHOTO_ONLY` | `1` | 只发照片时锚点钉在第 1 位 |
| `IMAGE_SKU_ATTRS` | `1` | "有没有黑色的 / 有XL码吗"走 SKU 数据(仅两路模式) |
| `IMAGE_PHOTO_RELATIONS` | `1` | "同品牌 / 同价位 / 搭配"以照片为锚点走多跳(仅两路模式) |

## 4. 视觉下限怎么定的

`python -m rag.eval.image_text_eval --calibrate`(CLIP 原始分数,与下限/融合设置无关):

| 样本 | n | top-1 相似度 |
|---|---:|---|
| 增强目录图(正样本,145×3) | 435 | min 0.508 · p01 0.592 · p05 0.695 · 中位数 0.805 |
| 合成无关图(噪声/纯色/渐变/文字/棋盘条纹/几何图形) | 50 | max **0.4835**(渐变图)· p95 0.481 · 中位数 0.437 |

取 "负样本最大值 + 0.02" 向上取整 = **0.51**:合成负样本 50/50 拒绝,增强正样本保留 434/435(99.8%)。
两个分布只隔约 0.02,真实照片的分数会比增强图低,所以宁可取低。

**这个下限只保证纯噪声 / 纯色 / 截图文字这类图不出随机卡,没有在真实的目录外用户照片上校准过。**
一张真实拍摄的、目录里没有的东西(比如一只杯子)很可能高于 0.51 并照样出 3 张"最像"的卡。

## 6. 局限

1. **CLIP 是英文训练的**,对中文营销图上的文字、细粒度型号(iPhone 17 Pro vs Pro Max)区分力有限;
   视觉锚点认错时,相对价格和"同一种东西"的判断都会跟着错。
2. **下限没用真实目录外照片校准**(见 §4)。真实照片比增强图难得多,§5 的数字是上限参考。
3. **上一轮的图片不会被记住**:只有当前这条 user 消息里的图片参与检索;"刚才那张图有没有便宜点的"
   这种跨轮引用拿不到图(文字会按普通追问走文字检索)。
4. 低于下限且文字有内容时走的是文字检索,但以 `llm_free=True` 调用:否定只按本地规则抽取
   (品牌提及 + 国别词,与 `extract_negation` 没配 key 时一致),比文字路径的 LLM 抽取弱一些
   (例如 "不要含酒精的" 这类属性排除不会生效)。这是"拍照路径零 LLM"的代价。
5. 描述性判断与否定解析都是规则:新句式需要补规则;属性词排除只看标题。
6. 英文配文时交叉编码器走多语模型 v2-m3(CPU 上更慢,冷启动见 CLAUDE.md §9.9)。

## 做法 A:离线图片描述写进文本索引(2026-10-07)

高星项目(RAGFlow、RAG-Anything、kotaemon)的主流做法是"图转文":入库时给每张图写一段描述,存进文本索引,
之后按普通文本走 BM25 / 向量 / 重排 / 硬约束。狮选照此补上:

- **生成**:`tools/caption_images.py`,本地 Qwen3-VL-2B-Instruct(Apache-2.0,transformers + Apple MPS,M4 上
  每张约 15–40 s,145 张一次性生成,**不调任何付费接口**)。提示词只让模型描述看得见的外观,不猜品牌 / 价格 / 功效。
  产物 `data/derived/image_captions.jsonl` 带模型修订号和提示词版本。145/145 解析成功(2 张图文字太多、输出被截断,
  按字段抢救)。
- **进索引的内容**:外观 + 颜色 + 材质 + 风格(chunk_type=`image_caption`)。**图中文字默认不进索引**
  (`RAG_CAPTION_INCLUDE_TEXT=0`):抽检看原图发现 2B 模型会编图里没有的字(帐篷图写出 "Tent" 和一串 "1000",
  插线板写出 "CUBO" "USB"),而品牌 / 型号本来就在商品 JSON 里。外观描述抽检准确(帐篷、插线板、跑鞋、耳机等)。
- **SKU 规格块**(chunk_type=`sku`):颜色 / 尺码 / 容量等结构化规格汇总成一段文字。"有没有黑色的"这类问题
  应该查结构化 SKU,不该靠看图——每个商品只有一张图,图里只看得到一种颜色。
- **评测(CI 同设置,无 LLM)**:文本索引 1082 → 1327 条(修复后,见下);golden 92 不变(recall@5 0.929 / MRR 0.863);
  compositional 61 recall@5 0.821 → 0.830、MRR 0.878 → 0.886,变化的 2 个 case 都是变好
  (三款手机对比 0.67 → 1.0;"华为以外的智能手机" 0.4 → 0.6),没有任何 case 变差。基线已按此刷新。
  幅度很小,不要夸大;它的主要价值是让"只发照片"的请求以后可以走文本那一路(见 PLAN 的做法 C)。
- **BM25 不加这两块**:`RAG_BM25_EXTRA_FIELDS=sku,caption` 实测无收益(golden MRR −0.002),保持默认关闭。

### 事故记录:规格块重复向量(2026-10-07,已修复)

第一版规格块里有 45 个商品的文本一模一样(只有一条"规格:标准")。在 VM 上按版本化 + 别名切到新集合后,
`store_parity` 判定不通过(对精确解 Milvus 更差 7 条):泛化查询("第一个和第二个比一下")的结果被这 45 个
完全相同的向量占满,而且 Milvus HNSW 不管 ef 设多大都只返回 45 条。处理:别名一条命令回滚到上一版
(线上无感知、无需重启);规格块改为跳过没有信息量的规格("标准 / 默认 / 均码"等单值),并在前面加商品标题,
100 个规格块全部不同。修复后 CI 同设置评测与之前一致。教训:派生文本块入库前要查重复,
一致性校验 + 别名回滚这套流程在真实问题上起了作用。

## 做法 C:两路召回 + 商品级 RRF(IMAGE_TWO_PATH,2026-10-07)

代码:`rag_client._image_two_path` / `_photo_relation`、`image_fusion`(`text_path_query`、`rrf_merge`、
`is_deictic_only`、`apply_sku_ask`)、`sku_attrs.py`、`multihop.detect_photo_relation`。单测:
`server/tests/test_image_two_path.py`。**整条路径仍然不调用任何 LLM**(文字路、关系路的检索都是
`top_k(llm_free=True)`;单测在配了假 key、开 `RAG_REWRITE=1` 的情况下拦截 urllib / httpx / openai 客户端,断言零请求)。

**流程**(视觉最高分低于下限、CLIP 不可用、约束清空视觉候选时与级联完全相同):

1. **关系问法优先**:"同品牌的 / 同价位的 / 配个什么 / 怎么搭" → 视觉锚点作为会话锚点交给
   `multi_hop_retrieve`(派生约束、断言、人民币归一化同一份代码);不满足关系的"放宽兜底"卡不出,
   也不为它多跑检索;结果再过本轮硬约束。"同品牌的**耳机**"这类能解析成品类的目标词作为目标品类;
   没说品类且细分品类里没有同品牌商品时放宽到大类。"这个牌子的质量怎么样 / 价格一样吗 / 有配件吗"不算关系。
   status=`relation`,不新增 SSE 事件类型。
2. **视觉路 V** = 级联的幸存者(下限 + 品类钉住 + 全部硬约束),纯视觉顺序,**不跑交叉编码器**。
3. **文字路 T** = 一次 `top_k`:范围是锚点的细分品类族 + 大类(用户文字点了别的品类就用文字的),
   硬约束同 V,结果再严格复查;细分品类族里为空时放宽到大类再查一次。query = 去掉指代 / 约束套话的文字
   (前面加锚点细分品类名);没有描述性内容时用视觉锚点的离线图片描述(做法 A)。
4. **RRF**:k=60、两路等权、**没有在评测集上调过**;同分按视觉名次、再按文字名次排序(确定性)。
   卡片 `retrieval_signals` 带 `visual_rank / text_rank / clip_sim / source`。
5. **钉住**:锚点满足约束时,以下情况放第 1 位——视觉最高分 ≥ `IMAGE_PIN_SIM`;辨认 / 指代式提问
   ("这个多少钱 / 这是什么 / 这是华为的吗 / 有没有同款",被问到的品牌不算硬约束);只发照片。
   用户在要"别的 / 其他款 / 换一款"时不钉。
6. **SKU 规格问法**("有没有黑色的 / 有XL码吗 / 有256G的吗"):只读商品 JSON 的 `skus[].properties`,三态
   (有 / 列了这一族但没有 / 没列)。锚点有 → 锚点第 1;锚点没有 → 只留 SKU 里有的候选,候选都没有时在目录同类里
   扫(同样过硬约束,**这些卡可能低于视觉下限**,trace 里 `source=sku_catalog`,附加段会说明视觉相似度较低);
   没列 → 不改卡片,告诉 LLM"SKU 数据没写,不能说没有"。确定性事实以附加段的形式交给 LLM。
   解析是保守的:不带"色"字的基础色只在像问颜色的位置算("网红款 / 奶粉的 / 定金的"不算),
   前置和后置否定("不要黑色的 / 黑色的不要 / 白色以外")都跳过,型号里的 XL / XS("Pixel 7 XL")、
   运存("64G运存")、"T恤"里的 T 都不当规格。

**开销**(4 vCPU VM,`RERANK_INPUT_CAP=10`、`RERANK_MAX_LENGTH=128`):与级联相比,有描述的请求把
"交叉编码器排 ≤20 个视觉幸存者"换成"一次文字检索(含 ≤10 对交叉编码器)";只发照片的请求**新增**一次文字检索
(级联原本不跑交叉编码器)。离线描述约 50–100 字,在 128 token 的重排长度里会挤掉一部分商品文本。
关系问法是 1–2 次带重排的 `top_k`。**都没有在 VM 上实测延迟。**

**评测**:`rag/eval/image_text_eval.py --two-path` → `docs/bench/image_two_path_eval_local.json`
(复审修正后的代码重跑,2026-10-07;本机 M4、Chroma、`RERANK_INPUT_CAP=10`、`RERANK_MAX_LENGTH=128`,
不调用任何 LLM;145 张商品图 × 3 个随机变体,与级联评测同一套变体和种子;错误 0)。

读法:

- **只发照片前 3 名掉了 0.7 个点**(3 例):文字路补进来的卡把本品挤出了前 3。第 1 名不变是因为只发照片时钉住;
  不钉住第 1 名掉到 0.862,所以钉住是必须的。
- **"便宜点"的 2.1%(3/145)两种模式一样**:都是 CLIP 把照片认成了别的商品,约束按认出的商品执行
  (相对视觉锚点违反为 0),不是两路引入的。
- 关系问法"有卡"比例低,是因为很多品牌在目录里只有这一件、同价位同品类也常常没有别的商品;
  这时不出"放宽兜底"卡,如实说没有。满足率是对**拍的那件商品**算的,对视觉锚点都是 1.0,
  差的部分来自 CLIP 认错锚点。
- 关系问法的"有卡"、SKU 的"锚点认对"都受 CLIP 第 1 名准确率(0.959)限制,两路没有改善这一点。
